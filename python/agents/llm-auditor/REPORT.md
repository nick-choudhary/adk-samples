# LLM Auditor - Technical Documentation Report

## Project Scope

### High-Level Summary
The LLM Auditor is an automated fact-checking system designed to evaluate and enhance the factual grounding of responses generated by Large Language Models (LLMs). It functions as a verification layer that analyzes LLM-generated content against real-world information, identifies inaccuracies, and optionally rewrites responses to correct errors.

### Core Capabilities
- **Claim Extraction**: Automatically identifies and isolates specific, verifiable statements within LLM-generated text
- **Fact Verification**: Determines the accuracy of claims using web search tools and internal knowledge
- **Detailed Reporting**: Produces comprehensive breakdowns listing identified claims with their verification status (Accurate, Inaccurate, Disputed, Unsupported, Not Applicable)
- **Response Refinement**: Optionally rewrites original responses to correct inaccuracies based on verified findings
- **Grounding Attribution**: Appends references and sources to support verification findings

### Primary Use Cases
- Quality assurance for LLM outputs in high-stakes applications
- Automated fact-checking for content generation pipelines
- Educational tools for teaching critical thinking about AI-generated content
- Publishing workflows requiring factual accuracy verification
- Research applications studying LLM hallucination and accuracy

### Target Users
- Content creators and publishers requiring factual accuracy
- Researchers studying LLM reliability and hallucination
- Developers building trustworthy AI applications
- Organizations implementing AI governance and quality control
- Educational institutions teaching AI literacy

### Key Innovations/Differentiators
- **Multi-Agent Architecture**: Separates concerns between criticism (fact-checking) and revision (correction)
- **Iterative Verification**: Supports iterative processing for improved accuracy over multiple passes
- **Grounding Metadata Integration**: Leverages Gemini's native grounding capabilities with custom reference rendering
- **Minimal Revision Strategy**: Maintains original structure and style while correcting only factual errors
- **Verdict Classification System**: Uses a structured 5-category verdict system for nuanced accuracy assessment

        self.agent = llm_auditor

        self.accuracy_threshold = accuracy_threshold

    def run(self, user_input: str, runner):
        """Run iterative fact-checking until quality threshold met."""
        current_text = user_input

        for iteration in range(self.max_iterations):
            # Run auditor on current text
            response = self._run_agent(current_text, runner)

def _add_confidence_scores(
    callback_context: CallbackContext,
    llm_response: LlmResponse,
) -> LlmResponse:
    """Add confidence scoring to verdicts."""
    if not llm_response.content or not llm_response.content.parts:
        return llm_response

    # Analyze grounding metadata for confidence
    if llm_response.grounding_metadata:
        num_sources = len(llm_response.grounding_metadata.grounding_chunks or [])

        # More sources = higher confidence
        confidence = min(num_sources / 5.0, 1.0)  # Cap at 100%

        confidence_text = f"\n\n**Confidence Score**: {confidence:.0%}"
        confidence_text += f"\n**Sources Consulted**: {num_sources}"

        llm_response.content.parts.append(types.Part(text=confidence_text))

    return llm_response

### 7. Implement Batch Processing

**Use Case**: Process multiple question-answer pairs efficiently

**Implementation**:

```python
# Create /home/user/adk-samples/python/agents/llm-auditor/llm_auditor/batch_processor.py

from google.adk.runners import InMemoryRunner
from google.genai.types import Part, UserContent
from llm_auditor.agent import root_agent
import asyncio
from typing import List, Dict

class BatchAuditor:
    """Process multiple QA pairs in batch."""

    def __init__(self):
        self.runner = InMemoryRunner(agent=root_agent)

    async def process_batch(self, qa_pairs: List[Dict[str, str]]) -> List[str]:
        """Process multiple question-answer pairs."""
        results = []

        for qa in qa_pairs:
            user_input = f"Q: {qa['question']}\nA: {qa['answer']}"
            result = await self._process_single(user_input)
            results.append(result)

        return results

    async def _process_single(self, user_input: str) -> str:
        """Process single QA pair."""
        session = await self.runner.session_service.create_session(
            app_name=self.runner.app_name,
            user_id="batch_user"
        )

        content = UserContent(parts=[Part(text=user_input)])
        response = ""

        async for event in self.runner.run_async(
            user_id=session.user_id,
            session_id=session.id,
            new_message=content
        ):
            if event.content.parts and event.content.parts[0].text:
                response = event.content.parts[0].text

        return response

# Usage
async def main():
    auditor = BatchAuditor()

    qa_pairs = [
        {"question": "Why is the sky blue?", "answer": "Because of water."},
        {"question": "What is 2+2?", "answer": "5"},
        {"question": "Who invented the telephone?", "answer": "Alexander Graham Bell"},
    ]

    results = await auditor.process_batch(qa_pairs)
    for i, result in enumerate(results):
        print(f"\n=== Result {i+1} ===\n{result}")

asyncio.run(main())
```
